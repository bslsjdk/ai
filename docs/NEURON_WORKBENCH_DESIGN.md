# 神经元工作台：资源竞争、训练与安全扩展

更新时间：2026-10-09

## 1. 从 DeepSeek 输出中借鉴什么

可借鉴的是工程机制，而不是把生物进化比喻当成已经实现的事实。

- **资源先有预算，再做复制。** 新单元先估算权重与对象成本，工作区超过 64 MiB 的估算数据/模型预算或超过数量上限时不准复制。4 GiB 仍然是整个 app 进程的硬上限，不是给神经元池单独使用的额度。
- **评分同时看任务贡献与成本。** 原始贡献分是屏蔽单元后验证集 MSE 的增加量。资源分数额外扣除估算存储和计算成本，两个值分开显示，避免用户误以为资源成本等于任务正确性。
- **复制有费用，变异有回滚。** 每代最多尝试剪一个非精英冗余单元，再复制一个得分最高的活动单元。复制前把父代输出贡献一分为二，避免仅因复制就把该路径的输出加倍；后代只做小幅变异。验证 MSE 超出 0.5% 容差就恢复父代权重并丢弃后代。
- **精英保护与渐进淘汰。** 不会按一次低分直接批量杀死大量单元；每次至多剪一个，验证集不允许的剪枝不会执行，至少留一个活动单元。
- **分离资源估算和真实测量。** Java 对象/数组成本是估算，设备上的进程 RSS/PSS/HWM 才是实际内存证据。训练/进化在进程 RSS 超过 3500 MiB 时停止启动，为 native runtime、QNN staging 和系统分配保留空间。

## 2. 对 4 GiB 计算的校准

假设每条稀疏边使用 FP32 权重和 32 位索引，理论数据大小是 8 字节/边。100 条边加 32 字节单元状态约 832 字节；这个数量级计算合理，但不是 Android/Java 中每个单元的真实内存占用。

实际运行还要计入数组和对象头、引用、对齐、评分/优化器状态、训练样本、验证缓冲、临时张量、日志、运行时、NPU 驱动与图缓存，以及内存分配器和页的开销。所以“4 GiB 除以 832 字节”只是理想化的原始数据上界，不能用来承诺手机可以运行数百万个对象。工作区也不该把 4 GiB 占满：这个 app 还保留原生 runtime 和 NPU 服务代码，项目的进程 RSS 硬上限是 4096 MiB，发布晋级目标是低于 3800 MiB。

## 3. 当前实现边界

本阶段是一个可解释的、数值型多输入 → 隐藏层 → 多输出网络：

- 输入维度 1–16，隐藏单元 1–128，输出维度 1–16，数据最多 5000 条，单次训练最多 5000 轮；训练计算量有独立估算上限。
- 隐藏单元使用 tanh，输出层是线性加权求和并包含可训练输出偏置。CPU 上运行 Adam；把样本划分为训练/验证部分，恢复验证集最佳权重，并使用早停。
- 每个隐藏单元可单独启用/禁用、计算消融贡献、复制到本地库、删除或导出。工作区 JSON 持久化模型权重、输出偏置、数据集、单元库、任务历史和事件。
- 文件导入支持有上限的 CSV/JSON 数值数据、工作区 JSON、单个神经元/神经元包 JSON 和训练任务参数 JSON；导出包含 CSV/JSON/JSONL。维度不匹配要先确认，网络结构重建会明确警告。
- 网络图绘制输入层、隐藏层与输出层连接；运行页会显示每个活动隐藏单元的激活值和对每个输出的贡献。
- 当前不是自然语言模型，不会直接理解任意中文任务描述。语言任务需要分词/编码、数据格式、目标函数、训练评估及推理路径，不能仅靠把文本放到 CSV 里冒充已具备。

## 4. 为什么现在不直接放开到几千个

当前权重保存为每个单元的小型输入/输出数组，所以它对 16 维输入、16 维输出和 128 个隐藏单元足够简单、可检查，但它不是大规模稀疏图的最终存储形式。把数量上限调成 10,000 而不改数据结构，可能只让内存、视图和训练时间先崩溃。

进入千级单元前必须补齐：

1. **稀疏连接表**：每条边存源/目标索引、权重与必要状态，支持 fan-in/fan-out 上限；不连接就不分配权重对象，不能只用稠密数组里的零值假装节省了内存。
2. **分层预算池**：网络/子网有独立配额，保留系统余量；复制前估算峰值和训练临时空间，剪枝后复用固定大小的块或 slab，减少频繁对象创建。
3. **真正的成本测量**：记录任务准确度、验证误差、延迟、计算量、内存变化和实际后端。NPU 只运行稳定、批量且能摊平提交开销的子图；动态拓扑、评分与进化先在 CPU 上执行。
4. **多任务和对抗验证**：防止结构专门过拟合单个小验证集或利用评分漏洞。探索配额要有上限，并跟踪它带来的真实泛化收益。
5. **快照、回滚与崩溃恢复**：进化每代都有可恢复的工作区；超预算时停止新分配而不是继续复制，保存要通过临时文件与替换避免半写文件损坏。

这是扩展门槛，不是声称当前代码已经具备稀疏百万神经元、自然语言学习或自动发现专业模块的能力。

## 5. 验证清单

- Java 与 Android 资源编译通过。
- NDK/CMake 编译与 APK 打包通过。
- APK manifest 的 launcher 指向 NeuronLabActivity；applicationId 和原签名身份保持不变。
- 新分支 APK 的发布日期和校验和对应本次构建，不能从 main 的旧 release 推断实验分支已发布。
- 真机从 8 个单元开始训练：验证集 MSE 下降、取消能工作、重启后模型/数据/神经元库仍在。
- 检查输入与输出维度边界、CSV/JSON 错误行、超大文件、单个/批量导入导出、全禁用保护、剪枝回滚。
- 真机测量 RSS/PSS/HWM；确认进程 RSS 留在 4096 MiB 以下且发布目标低于 3800 MiB。
- 独立运行 NPU 诊断，仅凭 QNN 成功调用不能声称泛化训练已经使用 NPU 加速。
