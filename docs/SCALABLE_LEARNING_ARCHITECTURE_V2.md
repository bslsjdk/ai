# 可扩展学习架构 V2：从浅层数值网络到可训练的模块化系统

状态：架构修订提案；尚未表示已实现或通过真机验证
更新时间：2026-10-10
目标分支：feat/scalable-neuron-architecture-v2

## 0. 结论先行

当前工作台的学习上限确实存在，但原因不是单一的“学习率太低”：

- 当前主工作台是单隐藏层 tanh + 线性输出的数值映射网络，输入/输出最多 16 维、隐藏单元最多 128、数据最多 5000 条。
- 它已有 CPU 反向传播与 Adam，不是纯 Hebbian，也不是完全不能学习；但浅层结构、窄输入/输出接口、受限数据规模和当前全批量训练路径，不足以直接扩展成通用语言模型。
- EvoNet16 是另一条隔离的进化实验路径，主要靠整体变异筛选。不能把它的进化更新和工作台的 Adam 训练混为同一个算法。
- 单纯提高 learning rate 不能解决表达能力和数据管线的上限，过高反而会造成发散。

V2 的主原则：**以可微分的反向传播作为可扩展的主要学习路径；局部 Hebbian/资格迹作为可选的在线适应机制；模块化稀疏网络与外部记忆负责扩展；每一级扩展必须有基准测试。**

## 1. 分清三个互不替代的机制

### 1.1 主训练：梯度学习

负责从大量样本中学习可复用的参数。每个可训练模块必须有明确的前向计算、损失函数、梯度、优化器状态、验证集与检查点。

- 数值回归：归一化后的 MSE/Huber。
- 分类/动作预测：softmax + cross-entropy。
- 语言建模：下一个 token 的 cross-entropy；不能用“预测误差”一句话代替完整训练目标。
- 优化器：先实现稳定的 mini-batch Adam/AdamW；支持梯度裁剪、学习率 warmup/衰减、验证集早停和最佳权重恢复。
- 学习率范围必须由配置、梯度范数和验证曲线共同决定。不得简单把 0.01 提高到一个很大的数来掩盖模型结构问题。

### 1.2 在线适应：资格迹与奖励调制

资格迹可用于迷宫等有延迟奖励的在线任务，但不应取代主训练的反向传播。

建议形式：

- e(t) = clamp(lambda * e(t-1) + local_pre_post_signal, -traceMax, traceMax)
- A(t) = reward(t) - rewardBaseline(t)
- deltaW = localLearningRate * A(t) * e(t)

要记录 reward baseline、trace norm、权重范数、更新范数和非有限值计数。需要与“无资格迹”“无奖励基线”对照，证明其对样本效率和长时信用分配的收益。局部更新不得无约束地作用于全部权重。

### 1.3 结构适应：增生、剪枝和专家路由

结构变化只负责调整容量与计算分配，不替代学习。新增模块必须通过验证集才能被接纳；剪枝必须可回滚；保留探索多样性，不能仅按最近 reward 排名杀掉低频但有用的单元。

## 2. V2 计算架构

### 层 A：编码器与任务头

不同任务使用显式编码器和输出头。迷宫先使用归一化数值特征；语言任务以后必须单独加入 tokenizer、token embedding、位置/序列状态、词表输出头和 token 级训练样本。

TaskAdapter 只负责数据/动作协议，不负责凭空赋予模型学习能力。

### 层 B：可训练模块

从小型可微分模块开始，逐步增加深度，而不是把一个隐藏层无限加宽：

1. 当前浅层网络作为兼容基线。
2. 多层 MLP + residual/skip connection，降低深层训练退化风险。
3. 对需要序列状态的任务，单独评估 GRU 类循环模块或其他有明确梯度路径的序列模块。
4. 采用块级模块接口，统一 forward/backward、参数计数、checkpoint 与验证接口。

初期不同时引入复杂循环、局部学习、动态拓扑和 GPU 后端；一次只引入一种新机制。

### 层 C：稀疏专家与路由

规模扩大后，网络以专家/子网为单位组织。路由器根据当前输入选择少数专家；每个专家内部仍使用经过验证的梯度学习。监控专家负载、路由熵、未被选择专家比例和任务表现，避免单个专家垄断或专家全部学成一样。

稀疏必须是真稀疏存储/计算：压缩连接数组、索引和连续权重块；禁止用大量 Java 神经元对象或稠密零权重冒充稀疏网络。

### 层 D：外部记忆

外部记忆保存文档、事实、任务轨迹、代码与可复用技能。它通过索引、检索、来源和更新时间访问，不计入神经网络参数量。检索内容仍需由模型判断和整合；知识库容量不等于推理能力。

### 层 E：运行时调度

- CPU：任务控制、数据准备、评分、路由、存档、回滚和小型基线训练。
- GPU：只有在批量张量计算的端到端基准证明收益后，才用于训练/前向。
- NPU：初期只用于形状固定、已验证的推理子图；不能声称它执行通用反向传播或动态稀疏学习。
- CPU/GPU 双缓冲属于后续优化，必须在单后端正确且可测量后再实现。

## 3. 学习能力与容量的扩展

不要以“神经元数量”作为唯一规模指标。每次实验同时记录：

- 参数总量、可训练参数量、每样本激活参数量、连接数和专家数。
- 训练/验证损失、任务成功率、样本效率、泛化差距和旧任务保持率。
- 每步/每 epoch 延迟、吞吐量、实际 RSS/PSS/HWM、峰值临时内存和能耗（能测量时）。
- 学习率、梯度范数、权重范数、更新范数、NaN/Inf 计数。

容量扩展触发条件：

1. 训练集与验证集都表现差：先检查数据、输入表示、优化器和欠拟合，再考虑扩容。
2. 训练集表现好、验证集差：先处理过拟合与数据泄漏，不得直接加神经元。
3. 验证损失长期停滞且数据/梯度管线经检查正确：才比较加深网络、加宽模块或新增专家。
4. 新结构只有在固定验证集上优于基线，且独立测试集没有回退时才晋级。

## 4. 设备内存安全

手机整个进程硬限制保持小于 4 GiB。训练开始前估算模型参数、梯度/Adam 状态、批次激活、样本缓冲、checkpoint 临时副本和 native/NPU 缓冲；启动后仍持续测量实际 RSS/PSS。

- 现有 3.5 GiB 左右启动保护应继续保留，不能把它当作允许占满的目标。
- 规模扩大时优先使用连续 primitive 数组、mini-batch、梯度累积、可复用工作区与分块加载，减少对象头和峰值副本。
- 超预算时停止新分配、保存最后一个完整检查点并返回明确错误；不得为了完成训练忽略内存限制。
- 不能仅凭“每个神经元估算 200 字节”承诺百万级可运行。

## 5. 实施阶段与验收门槛

### P0：核实现有学习基线

- 对当前 Adam 反向传播做数值梯度检查。
- 记录多个学习率/批次大小下的训练与验证曲线，检查输入/目标归一化。
- 固定随机种子和数据拆分；验证最佳检查点恢复、取消和重启续训。
- 保留现有 128 隐藏单元实现作为 baseline，不把它说成最终架构。

### P1：可配置深度与 mini-batch

- 抽象可训练层接口和参数块。
- 新增 2–4 层的 residual MLP 实验模式；旧 workspace JSON 仍可读取，旧网络不会被静默覆盖。
- 加入 mini-batch、梯度裁剪、学习率调度和可恢复优化器状态。
- 先在数值任务上证明多层网络训练稳定。

### P2：迷宫学习基准

- 保留 Evo16 进化基线。
- 增加可微分策略网络，使用固定训练地图与独立验证/测试地图。
- 比较监督动作学习、奖励学习和资格迹辅助学习，逐项消融。
- 目标可以设为 100 张固定测试地图成功率 90%，但未实测前只是验收目标，不是承诺。

### P3：稀疏模块与可控扩容

- 从 128 → 256 → 512 → 1k 逐级测试；每一级必须先通过性能、内存和泛化门槛。
- 将连接和权重改为连续稀疏存储，再考虑 Top-K/专家路由。
- 结构扩张/剪枝都保留快照与验证回滚。

### P4：语言模型研究分支

- 单独实现 tokenizer、token 序列数据管线、embedding、序列模型、输出词表、next-token cross-entropy、反向传播和 checkpoint/resume。
- 与小型标准语言模型基线比较困惑度、验证损失、生成质量和训练 token 数。
- 外部检索可扩充可访问知识，但不得宣称等价于模型参数内化的知识。
- 只有经过语言基准验证后，才讨论与 9B 模型的能力比较。

## 6. 当前明确不宣称的能力

本架构文件不代表当前应用已经实现多层 residual 网络、通用稀疏专家、百万级网络、完整语言模型训练、GPU 训练或 NPU 训练。它定义的是下一阶段的工程路线与验收条件。每项能力必须由代码、构建记录和可复现实验分别证明。
