# 从独立神经元单元到语言模型：当前实现边界与 PK 路线

更新时间：2026-10-10

## 当前已经落地的内容

`scripts/train_composed_neuron_lm.py` 是一个从零训练、CPU 可运行的字符级语言模型，不加载 Qwen 权重。隐藏层中的每个神经元都作为独立记录保存，具有自己的 ID、输入权重、偏置、输出权重、启用状态和更新计数。训练时这些单元组合成前馈网络，对下一个字符做概率预测；模型权重和训练报告写入 `experiments/composed-neuron-lm/latest/`。

自动化工作流 `.github/workflows/composed-neuron-language-model.yml` 在 CPU runner 上训练三个固定随机种子，并自动把模型检查点、逐轮日志和汇总 JSON 提交回实验分支。

## 不能混淆的三种系统

1. **预训练基线**：Qwen2.5 是外部已有的 Transformer，用于测量目前通用语言模型的基线。
2. **此前控制实验**：GridWorld 的小型 Q 网络验证学习机制，不是语言模型。
3. **当前自建模型**：显式神经元单元组成的字符级预测网络，从随机初始化开始学习一个合成文本语料。它是“独立单元组合成网络并进行语言建模”的最小可执行原型，但能力远小于通用 LLM。

## 目前还没实现的部分

- 目前连接是固定的一层全连接输入到隐藏单元、隐藏单元到输出层，不是动态稀疏图。
- 还没有依据验证贡献自动增删连接、复制/合并单元、分层路由或专家协作。
- 语料是合成的算术格式文本，不是高质量大规模自然语言语料；结果不能与 Qwen 的问答准确率直接横向比较。
- 字符级、固定窗口模型不能建模任意长度的上下文，也不等于完整的推理语言模型。

## 后续阶段与通过条件

### 阶段 A：确认基础闭环
固定语料哈希、三组随机种子、独立保留测试集；报告参数数、训练耗时、验证交叉熵、下一个字符准确率、基线交叉熵、模型文件和原始日志。首先要求模型稳定优于 unigram 基线。

### 阶段 B：神经元组合机制消融
在参数量和训练预算匹配下，比较：
- 固定全连接隐藏单元；
- 稀疏连接的独立单元池；
- 按验证集贡献选择/屏蔽单元；
- 允许复制、变异、剪枝并能回滚的动态拓扑。

同一数据切分、相同种子集合，记录准确度、交叉熵、推理延迟、参数数、实际峰值内存。任何动态结构只有在独立测试集稳定获益时才保留。

### 阶段 C：从字符建模走向真实文本任务
接入可复现的分词器与公开许可语料，增加中文/英文、指令遵循、组合泛化、长程依赖和多步推理任务。必须同时保留相同数据、量化精度、上下文预算、训练 FLOPs/时间等公平比较条件。

### 阶段 D：与预训练语言模型正面对决
将自建模型与公开基线放在共同任务集上评测，分开报告正确率、校准/格式遵循、长上下文、泛化、速度、峰值内存和训练成本。只有同一任务、同一评分规则和可复现的多次运行结果才算 PK；不拿合成字符预测分数冒充通用推理胜利。

## 资源与诚实性约束

当前阶段在云端 CPU 上训练，参数和批量有上限。未来若移植到手机，仍必须遵守项目约定的整个进程运行时内存低于 4 GiB 的硬约束。当前报告会明确写出数据与架构限制，不把一个能拟合字符模式的小模型宣传成通用智能。


## 已验证实验：固定稀疏 vs. 动态重组（2026-10-10）

脚本：`scripts/compare_sparse_dense_neuron_lm.py`、`scripts/test_dynamic_sparse_neuron_lm.py`。工作流分别为 `.github/workflows/sparse-dense-neuron-lm-ablation.yml` 与 `.github/workflows/dynamic-sparse-neuron-lm.yml`。

在同一合成字符语料、3 个随机种子和 24 轮训练下，参数量几乎完全匹配（动态稀疏 1,570；全连接 1,569）：

| 结构 | 平均验证字符准确率 | 平均验证损失 | 平均训练时间 |
|---|---:|---:|---:|
| 固定随机稀疏连接 | 50.63% | 2.094 | 1.87 s |
| 动态重组，12.5%/轮 | 70.63% | 1.297 | 2.03 s |
| 动态重组，25%/轮 | 67.92% | 1.401 | 1.96 s |
| 动态重组，37.5%/轮 | 58.22% | 1.701 | 1.98 s |
| 参数匹配全连接 | 72.37% | 1.193 | 1.25 s |

完整数据：`experiments/dynamic-sparse-neuron-lm/latest/summary.json`。动态模型会按神经元 ID 保存输入连接索引、输出 token 索引、权重范数及单元消融造成的验证损失变化，可用于检查哪些单元实际有贡献。

**解释边界：** 动态重组明显优于固定随机稀疏，但目前仍比全连接低约 1.74 个百分点，并且训练更慢。这只是小型合成字符任务上的结构实验，不代表通用语言推理能力，也不证明动态稀疏在其他任务上必胜。当前下一步应把同样的可审计单元拓扑和贡献分析迁移到真实文本/组合泛化任务，再决定是否值得扩大模型。


## 真实聊天模型基线（2026-10-10）

工作流 `.github/workflows/llm-pk-benchmark.yml` 已在 CPU 的 `llama.cpp` 推理后端运行同一套 90 道诊断题，使用固定 Q4_K_M 量化模型与确定性解码。原始逐题输出已保存到 `experiments/llm-pk/latest/`。

| 模型/模式 | 总正确 | 准确率 | 平均单题耗时 |
|---|---:|---:|---:|
| Qwen2.5-0.5B-Instruct Q4_K_M，单次回答 | 54/90 | 60.00% | 0.317 s |
| Qwen2.5-0.5B-Instruct Q4_K_M，二次验证 | 51/90 | 56.67% | 0.743 s |
| Qwen2.5-1.5B-Instruct Q4_K_M，单次回答 | 66/90 | 73.33% | 0.687 s |

1.5B 模型分类准确率：算术 95.83%（23/24）、上下文回忆 100%（16/16）、演绎 62.5%（10/16）、指令格式 60%（6/10）、数列 91.67%（11/12）、状态更新 0%（0/12）。状态更新类别所有基线都未答对，应该保留为一个明确的失败点，后续检查提示设计与模型能力，而不是把它藏掉。

**公平性边界：** 这组结果是现成 Qwen 模型的诊断基线，不是自建神经元模型的 PK 成绩。当前自建模型只在合成字符预测任务上评测；在把自建模型接入同一问答接口并使用完全相同的 90 道题之前，不能直接比较两边的准确率。该题集是本项目生成的诊断套件，不是公开排行榜，也不足以证明通用智能。


## 长期目标：以更低参数预算反超 9B 级语言模型

目标不是在合成题上刷一个好看的分数，而是逐步训练出从零开始、由可检查的神经元单元构成的语言模型，并最终在明确的共同测试集上超过约 9B 参数级基线，同时显著减少可训练参数和推理资源。此目标是长期研究目标，当前原型距离目标还很远。

### 阶段路线与晋级条件

1. **真实文本闭环**：用公开领域文本从随机初始化训练循环神经元网络；保存数据哈希、参数量、训练预算、验证损失、bits/character、生成样例和单元消融。
2. **结构消融**：在同一数据切分和近似参数预算下比较普通全连接、固定稀疏、动态重组和循环神经元。多个随机种子报告均值与波动，记录速度及内存；不因单次胜出就宣布结构优越。
3. **扩展语料与分词**：从单书字符预测推进到多来源、许可清晰的文本；对比字符、字节与子词表示，避免把字符级困惑度直接当作聊天能力。
4. **语言能力测试**：训练指令格式、事实检索、组合泛化、多步状态更新与长上下文测试。训练、验证、测试数据必须隔离，并保留逐题错误。
5. **公平的 9B PK**：固定测试集、提示词、解码参数、量化精度与硬件；同时比较任务质量、校准、上下文长度、延迟、峰值 RAM、模型文件大小、训练计算量和能耗。对比必须明确“参数量”究竟是总参数、激活参数还是每 token 实际执行参数，不能把不同定义混为一谈。
6. **移动端约束**：任何面向手机的推理方案都必须满足项目的运行时 RAM 小于 4 GB 硬约束；云端训练成绩不能代替设备实测。

### 当前基线位置

截至 2026-10-10，动态稀疏重组只在小型合成字符预测任务上优于固定随机稀疏网络，但略逊于参数量匹配的全连接模型。现成 Qwen 的 90 题诊断结果是外部参考，不能和自建模型的字符级准确率直接横向比较。下一步先建立真实文本循环神经元 LM 的可复现基线，再做同预算结构消融；不会提前宣称已经反超任何 9B 模型。
