# 二代超级神经元（Super Neuron V2）设计提案

状态：设计提案 + 第一版独立 Java 原型已实现；尚未接入生产语言训练管线  
目标分支：`feat/scalable-neuron-architecture-v2`  
设计原则：多信号输入、多路条件输出、可学习的内部状态、稀疏激活、可组合与可保存；不宣称单个单元本身就是完整语言模型。

## 1. 核心判断

这个方向可行，但需要把“超级神经元”定义成一个**有明确接口的小型可训练计算模块**，而不是把一个普通神经元简单加大。它可以在一个模块内部整合多路输入、保存有限的短时状态、选择性调用内部专家，并发出多种输出信号。这样一个模块可以替代许多重复的低级计算单元。

不能把它理解成“输入一个字，神经元里硬编码这个字，然后原样吐出来”。语言需要上下文、顺序、组合和泛化。相同 token 在不同上下文中应能产生不同的后续预测；因此文本输出应是 token 概率分布/候选分数，而不是固定的一对一查表。

## 1.1 重新明确目标：语言系统的基础单元

本项目中的“超级神经元”首先是**语言学习系统的基础计算单元**，不是迷宫控制器，也不是单纯把普通神经元封装成更大的对象。目标是让大量超级神经元形成可组合的语言处理网络，学习从 token 序列到上下文表示、关系、语义和后续 token 的映射。

关键设计要求：

- **处理片段而不只处理单个数字**：单元可以接收 token 表示、上下文向量、关系候选、位置/时间信息和来自其他单元的消息。
- **多路输入、多路输出**：一个单元可以融合不同来源的信号，并输出多个带类型的表示或候选；输出不是必须只有一个激活值。
- **携带有限状态**：能够把当前片段与前文状态结合，表达上下文变化；长文本记忆仍交给独立记忆系统。
- **学习组合关系**：同一 token 在不同上下文中可以产生不同的内部表示和输出；单元不能把词与词的关系固定成硬编码查表。
- **大规模协作、稀疏执行**：系统里可以有许多单元，但每个 token 步骤只运行相关的单元和边；“存在于网络中”不等于“每次都执行”。
- **端到端可训练**：单元的路由、融合与输出必须能通过语言目标学习；不能只靠人工给每个单元规定“它负责语法”就期待它自然变聪明。

### 语言系统中的单元协作示例

输入序列“我把书放在桌上，因为它很稳”时，系统可以让多个单元交换不同类型的候选信号：token 表示、词序与局部组合、实体/指代候选、上下文状态和下一 token 的候选分数。网络综合这些信号来预测后续 token。这里的“词法单元”“关系单元”“上下文单元”等只是可供实验的功能视角，不应一开始把每个单元永久锁死在人工指定的职责里；具体专长应由训练与路由逐步形成，并用消融实验验证。

这类结构的研究重点是：比同等参数预算的标准 Transformer/小型语言模型，是否更节省实际计算、是否更易增量扩展、是否能让模块产生可复用的专长。它**不会仅凭架构命名就自动超过 Transformer**，必须在同一语料、同一 token 化方式、相近参数量与计算预算下对照测试。

## 2. 单个超级神经元的结构

每个 SuperNeuron V2 由以下部分组成：

1. **多路输入端口**：接收来自多个上游单元的信号包。每个包包含信号类型、来源 ID、任务/序列 ID、时间步、置信度和载荷引用。载荷可为标量、低维向量、离散 token ID 或稀疏特征；不要求所有信息都展开成一个巨型稠密数组。
2. **输入适配器**：按类型把不同信号投影到共同的内部向量空间，同时保留来源/类型信息。无效或缺失输入要有明确 mask，不能把“没有信号”误当成数值零。
3. **融合与门控**：学习每路输入的权重，并按任务与上下文决定哪些信号有用。门控可以抑制无关信号，也可以融合相互补充的信号。
4. **内部状态**：小型向量状态保存短期上下文。状态有明确的 reset、detach、checkpoint 语义，避免不同任务或不同网络个体之间意外串状态。
5. **稀疏专家槽（可选）**：模块可以拥有多个小型可训练专家，但每次只激活 Top-K 个。未被路由到的专家不参与该次计算和更新。路由要有负载均衡/防塌缩监测，避免所有输入永远走同一个专家。
6. **多路输出头**：不同输出端口各有类型与用途，例如文本 token logits、动作分数、分类结果、记忆写入候选、控制信号。输出头共享融合后的内部表示，但各自有独立投影与损失，不要求每路输出相同格式。
7. **学习接口**：训练时记录本次被激活的路由、输入来源和必要的短期状态，以便梯度训练或受控的局部奖励更新准确归因。

概念计算流程：

`输入信号包 → 类型适配/掩码 → 门控融合 → 内部状态更新 → Top-K 专家（可选）→ 多路输出头`

这是模块内部的计算图，不是固定的“输入层—隐藏层—输出层”全局 MLP。多个模块之间可以建立稀疏、有向、可循环的连接。

## 3. 信号与端口协议

每个端口必须声明：

- `portId`：在该个体内稳定且唯一；
- `signalType`：如 TOKEN_ID、VECTOR、SCALAR、ACTION、MEMORY_KEY、MEMORY_VALUE、CONTROL；
- `shape/schema`：载荷维度或结构版本；
- `sourcePolicy`：允许的来源或路由类别；
- `timestamp/sequenceId`：用于排序与过期判断；
- `mask/confidence`：区分缺失、低置信度与有效零值。

多个输入的到达顺序不可被隐式忽略。序列任务必须携带位置/时间信息；并发事件需要明确的聚合规则。输出端口也必须带类型，不应只输出一组没有语义的 double。

## 4. “输入不同字，输出不同信息”如何实现

示例仅说明接口，不代表已经具备语言能力：

- 输入 token “你”后，输入适配器产生 token 表示，内部状态与上下文一起参与计算，文本输出头产生下一 token 的概率分布。
- 输入 token “我”会产生不同表示，但最终输出仍取决于上下文、任务和训练所得参数。
- 输入序列“你是谁”时，模块要按正确顺序整合多个 token；下一步预测由整个序列上下文共同决定，而不是把每个字分别查表。
- 同一输入在不同上下文下可以产生不同输出；不同输入也可能共享部分内部特征。

要训练语言模型，必须有大量 token 序列与 next-token 目标，采用交叉熵损失及合适的梯度传播。仅用迷宫奖励或简单的局部共现更新，不能代替语言训练。若目标是动作控制，可使用动作损失或强化学习目标；不同任务的损失应明确隔离与加权。

## 5. 为什么它可能减少普通神经元数量

它可以把一组高度相关的操作封装成一个可复用模块，并通过稀疏专家路由让每次只运行相关部分。但“一个超级神经元”内部依然包含参数、乘加、状态和内存；把 1000 个普通神经元包装成一个对象不会自动减少计算量。

必须分别测量：
- 完成同一任务所需的参数总量；
- 每 token / 每次事件实际执行的乘加与访存；
- 激活模块数、Top-K 命中率和路由负载分布；
- 训练样本效率、泛化准确率与延迟；
- checkpoint 大小、峰值 RSS/PSS 和能耗。

只有在相同任务质量下减少总计算/内存，才能说它确实更高效。

## 5.1 核心优化目标：少量超级神经元，承载更多有效能力

本项目应把“减少单元数量与内存占用”作为首要设计约束之一，而不是先造大量单元再试图压缩。目标是在**语言任务质量达到预设门槛**的前提下，尽可能降低常驻参数、每步激活状态、临时工作区与实际计算量。

必须区分四个量，不能只数神经元对象：

1. **单元数量**：网络里登记了多少个逻辑单元。
2. **独立参数量**：所有不共享的权重总数。一个超级神经元如果各自复制庞大权重，单元数虽少，总参数仍可能很大。
3. **常驻内存**：模型权重、拓扑、索引、优化器状态和运行时对象占用。
4. **每步激活成本**：当前 token 真正执行的计算、临时向量、缓存和访存量。

### 推荐先验证的紧凑设计

- **共享核心 + 小型单元专属参数**：多个超级神经元共享主要变换参数，只保留小型 ID/类型嵌入、门控参数或低秩适配器。这样增加逻辑单元时，不必按比例复制整套权重。共享也可能造成专长冲突，因此必须与不共享版本对照。
- **紧凑的内部表示**：使用有界维度和明确的数据类型；避免每个端口、每条边都创建多个 Java 对象。大批量数据优先使用连续的原始数组与紧凑索引。
- **按需计算，不按需复制模型**：单元可以很多，但每一步只运行被路由选中的少量单元。不要为了“激活”一个单元就复制一份完整参数。
- **训练与推理分离**：推理时不保留梯度、优化器状态和训练用激活缓存；训练检查点与推理模型采用不同的存储布局。
- **可选量化**：在数值稳定性测试通过后，再评估低精度权重与状态。量化不是免费的，必须检查语言质量和实际运行时支持。
- **内存预算器**：分别统计权重、状态、缓存、图结构和临时分配；接近 3.5 GiB 时停止扩容并保存，任何时候都不得突破 4 GiB 的运行时内存硬限制。

### 必须进行的公平对照

建立至少三组同任务实验：

A. 普通小型神经网络/图网络基线；  
B. 每个超级神经元都有独立参数的版本；  
C. 共享核心、少量专属参数、稀疏激活的紧凑版本。

固定语料、tokenizer、训练/验证切分和训练预算，记录验证损失/困惑度、参数总量、峰值 RSS/PSS、每 token 延迟、实际激活单元数与计算量。既要报告相同参数预算下的结果，也要报告达到相同质量门槛时的内存差异。

如果紧凑版本只是单元数少了、但总参数、内存或损失没有改善，就不能宣称它成功替代了大量普通神经元。反过来，如果它用更少常驻内存达到可比质量，才有证据支持这条路线。

## 5.2 超级神经元之间的协作与扩展

第一版协作运行时已新增为独立类 `SuperNeuronNetworkV2`，不替换旧图运行时。它将“逻辑单元数量”和“独立参数数量”分开处理：

- **共享计算核心**：所有逻辑单元共用一组小型输出通道参数；每个单元只保存自己的偏置和递归状态，避免每个单元都复制整套权重。
- **稀疏有向连接**：使用原始数组与前向星邻接表保存连接，不为每条边创建 Java 对象。连接可以形成多层、分支或循环结构。
- **多通道消息**：每条连接指定源单元的输出通道和目标单元；单元的输出通过连接权重变成下一步的输入信号。
- **同步协作**：当前时间步先选择要激活的单元，再发出消息供下一步消费，避免结果依赖遍历顺序。
- **Top-K 激活预算**：每步只激活输入信号绝对值最高的至多 K 个单元；未被选中的单元不执行本步计算。
- **稀疏信号缓冲**：使用 generation-stamp 和 touched-node 列表，避免每个时间步清空全部节点数组。
- **奖励调制原型**：提供局部资格迹与受限奖励更新，作为协作实验基线；这不是完整的语言模型反向传播，也不能替代 token 级监督训练。

当前实现允许构建 1,000 个逻辑单元、16,000 条连接的测试网络；构造器上限更高不代表手机上已验证能安全运行到该上限。实际容量必须由真实设备 RSS/PSS、延迟和任务质量测量决定。共享核心可能减少参数，但也可能限制不同单元形成独立专长，因此必须和独立参数版本做对照。

## 6. 与现有图网络 V2 的关系

建议保留现有 `SelfOrganizingNeuronGraph` 作为**底层稀疏连接与实验基线**，新增独立的 `SuperNeuronV2` 与 `SuperNeuronGraphRuntime`，不要直接把现有图类改成不兼容的全新语义。

- 图运行时负责稳定 ID、稀疏连接、任务调度、预算、保存/恢复。
- 超级神经元负责多输入融合、内部状态、门控、可选专家与多输出头。
- 个体管理器负责每个网络的身份、配置、训练记录、验证记录、导入/导出。
- 训练器负责样本批次、损失、梯度/优化器、验证集与检查点。
- 记忆系统负责长时信息；超级神经元的内部状态只承担受限的短期上下文，不代替长期记忆库。

初版先让一个超级神经元通过确定性单元测试，再把 4–16 个模块连成小图；最后才接入迷宫或 token 序列训练器。

## 7. 百万级规模与手机约束

当前图运行时上限仍是每图 1000 个节点/16000 个连接槽。超级神经元设计本身**不会**让百万节点自动可运行。百万级版本需要：

- 分页/分块存储和稳定的全局 ID；
- 只加载活跃页、只遍历活跃边；
- 稀疏事件队列和 Top-K 路由；
- 惰性更新资格迹，避免每步扫描所有边；
- 分块检查点、可取消任务和崩溃恢复；
- 运行时内存预算器，在接近 3.5 GiB 时停止扩容、保存检查点，绝不越过 4 GiB 总运行时内存硬限制。

先在小规模上测正确性与收益，再扩大规模。不要先把数组上限改成一百万，然后等手机替我们进行热力学实验。

## 8. 分阶段实施

### 阶段 A：独立模块原型
实现多输入/多输出协议、内部向量状态、门控、可选 Top-K 专家、序列化和确定性 seed。暂不改旧图运行时。

### 阶段 B：单元测试
测试输入顺序与 mask、多个输入产生不同表示、多输出头互不串值、状态 reset、稳定 ID、Top-K 上限、保存/恢复一致性、非法 shape 和非有限值拒绝。

### 阶段 C：小图基准
将 4–16 个超级神经元连接成可循环稀疏图，与同参数预算的普通图/小 MLP 比较任务质量、参数量、实际计算量、延迟和内存。

### 阶段 D：训练闭环
先用小型 token 序列任务验证 next-token 学习与泛化，再接入大数据训练管线。训练、验证和测试数据必须分离；保存最佳验证 checkpoint，不只保存最后一次权重。

### 阶段 E：可扩展运行时
在实测证明模块有收益后，再实现分页图、活跃边调度和多任务并发队列。并发个体的数量不等于同时激活数量；调度器按优先级、活动预算和内存预算决定谁运行。

## 9. 验收标准

不能只用“输出看起来像对的”作为验收。至少要求：
- 相同输入/seed 可重复；
- 不同输入在训练后能产生可测的不同输出；
- 未见过的组合也有一定泛化，而非仅记住训练样本；
- 多输出端口的类型、顺序与内容稳定；
- 检查点往返后输出与状态一致；
- 在相同质量门槛下报告参数、延迟、计算量和内存对照；
- 手机实测总进程内存始终低于 4 GiB。

**结论：** 二代超级神经元是面向语言学习的模块化计算单元。它应能整合多种语言相关信号、维护有限上下文、生成多路有类型的输出，并与大量其他单元协作形成更复杂的语言系统。它要挑战的是“简单单元缺乏丰富交互能力”这一工程限制，但是否比标准语言模型更有效，必须通过可复现的训练与基准对照证明。
